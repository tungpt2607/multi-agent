## Điểm 1. Phân tích lệnh Bash + allowlist (BR1-3, BR5, BR10, R2, G2)

| | 1A Tokenizer stdlib, fail closed (Khuyến nghị) | 1B Parser AST `bashlex` | 1C Cú pháp tối giản |
|---|---|---|---|
| Cách làm | Tiền xử lý: chỉ chấp nhận heredoc có delimiter trong nháy (`<<'EOF'`, không mở rộng) và đúng 2 mẫu commit: `git commit -F - <<'EOF'...` và `git commit -m "$(cat <<'EOF' ... EOF\n)"`; thân heredoc thay bằng placeholder. Sau đó `shlex.shlex(punctuation_chars=True)` tách token, cắt đoạn theo `; && \|\| \|` và xuống dòng; mỗi đoạn: token đầu phải trong allowlist, lệnh con git kiểm riêng, chuyển hướng chỉ cho `>/dev/null`, `2>/dev/null`, `2>&1`. Bất kỳ `$(`, backtick, `<(`, `>(`, `eval`, `exec`, `source`, `.`, `bash/sh -c`, `python3 -c`, `python3 -`, `X=y cmd`, `sudo`, `xargs`, `git -C/-c`, `find -exec/-delete` còn lại sau tiền xử lý, hoặc shlex lỗi -> deny | Dùng thư viện `bashlex` dựng AST, duyệt node command/redirect/substitution | Chỉ cho một lệnh đơn hoặc nối `&&`; không heredoc, không `$()`; commit dùng `git commit -F .agents/state/commit_msg.txt` (Điều phối viết file bằng Write) |
| Ưu | Không phụ thuộc ngoài; đạt AC2/AC4 (nội dung `-m`, mẫu grep, email không bị xét); dễ test | Chính xác hơn với cú pháp phức tạp | Đơn giản nhất, bề mặt lách nhỏ nhất |
| Nhược | Phải tự viết tiền xử lý heredoc (chỗ dễ sai nhất, cần ca test lách); cú pháp lạ bị chặn nhầm | Thêm phụ thuộc pip (máy người dùng phải cài); bashlex không hỗ trợ đủ cú pháp -> vẫn phải fail closed | Trái AC4 (heredoc commit) -> phải sửa spec; bất tiện |
| Đảo ngược | Có (thay hàm `check_bash`) | Có | Có |

Allowlist đề xuất (áp cho Điều phối và reviewer; agent khác vẫn bị cấm Bash như gate.py:187-188). Người dùng duyệt/sửa (G2):
- Đọc tệp/trạng thái: `ls pwd cat head tail wc grep rg find stat file diff sort uniq cut jq echo printf date true test`. Đối số đường dẫn tuyệt đối hoặc `..` ra ngoài dự án -> deny (trừ `/dev/null`) => `ls /` bị deny (AC9). Đối số khớp `.env`, `id_rsa`, `*.pem`, `printenv/env` -> deny (BR10).
- git chỉ đọc: `status diff log show rev-parse merge-base ls-files blame remote -v branch` (`branch` không kèm `-d/-D/-m/-f/-c`), `config --get`.
- git ghi cục bộ: `add`, `commit` (cấm `--amend`, `--no-verify`), `switch` (chỉ tới `main` hoặc `agent/REQ-\d{4}`, `-c` chỉ với `agent/REQ-\d{4}`; lý do: switch sang nhánh lạ có thể thay `.claude/` đang chạy).
- Chạy test: `pytest`, `python3 -m pytest`, `python3 -m py_compile`.
- Cần phiếu (điểm 2): `git push`, `git merge` (cấm `-f/--force*`, `--delete`, `--mirror`, `--all`, refspec có `:` trừ dạng `nhánh:nhánh` cùng tên).
- Mọi thứ khác: deny, lý do tiếng Việt (AC9). Không có lệnh Bash nào được ghi tệp -> BR2/BR7 tự thoả; Điều phối ghi `.agents/` bằng Write/Edit như cũ.
Rủi ro tồn dư: `pytest` chạy mã Python tuỳ ý trong `tests/` (có thể ghi `.agents/`). Giảm bằng: test chỉ dùng thư mục tạm (ART-0021 AC chung), reviewer đọc test trước khi chạy. Cần người dùng chấp nhận (câu hỏi Q1).
